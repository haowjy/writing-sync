# Drive sync index schema (version 1)

The index is user configuration, not credentials or a remote binding database.
Use CLI index edits where possible; manually edited YAML undergoes the same
validation. Unknown fields, duplicate keys, unsafe YAML and other versions fail.

```yaml
version: 1
kind: drive-sync
id: 590b7d30-bc08-45e3-aee3-f6bbfdac6342
auth: personal
roots:
  notes:
    path: /external/notes
    destination_name: Notes
    destination_parent: 1F3D4GWjbWumHn3HdECIHBVW0b2aBzIzL
selection:
  include:
    - root: notes
      path: .
      glob: "**/*"
  files: []
  exclude:
    - root: notes
      glob: "private/**"
policy:
  default_storage: google-doc
  formats: [markdown, text, html, epub]
  overrides:
    - root: notes
      glob: "originals/**"
      storage: original
```

## Fields

- `version`: integer `1`; booleans are not version numbers.
- `kind`: exactly `drive-sync`. Publishing uses a separate future index.
- `id`: UUID generated by `index create`. Preserve it across edits; changing it
  does not migrate existing remote ownership or baselines.
- `auth`: simple named OAuth profile (letters, digits, hyphen, underscore).
- `roots`: mapping of simple root names to `destination_name` and exactly one of
  `path` or `env`. `env` names an environment variable containing the root path.
  Optional `destination_parent` is a Drive folder id granted with
  `auth pick-folder`. The mirrored root folder is created inside it. Without it,
  the root is created in My Drive. Workflow:
  [destination parent](destination-parent.md).
  Relative root paths resolve from the index directory, never the current working
  directory. Destination root names must be unique within the index.
- `selection.include`: list of `{root, path, glob}`. The path names an included
  directory; its glob matches relative to that directory.
- `selection.files`: list of exact `{root, path}` source files.
- `selection.exclude`: list of `{root, glob}` matching root-relative paths.
  Exclusions win even over individually selected files.
- `policy.default_storage`: `google-doc` or `original`.
- `policy.formats`: conversion formats from `markdown`, `text`, `html`, `epub`.
  This list does not automatically exclude unrelated files matched by selection;
  select original storage or explicitly exclude unsupported files.
- `policy.overrides`: list of `{root, glob, storage}` matching root-relative paths.
  Overrides change storage, not selection. Different matching storage values
  conflict; there is no last-match-wins ordering.

All displayed top-level keys are required. Empty mappings/lists are valid where
shown. Selectors use relative POSIX paths: no absolute paths or `..` traversal.
`*` matches within a path segment; `**` spans zero or more segments. Selected
symlinks, nonregular files and overlapping roots are rejected.
Preview order is natural path order with exact path spelling breaking ties such
as `2.md` and `02.md`. It does not configure Drive sibling ordering. If a directory
cannot be scanned completely, `source_scan_failed` names that directory and stops
selection. Restore access and preview again; a partial scan is not an empty tree.

## Layout and lifecycle

Only ancestors of selected files become folders; empty folders are omitted.
Remote filenames retain source extensions, so `note.md` and `note.txt` do not
collide. Local folder layout is authoritative; remote moves are conflicts, not
instructions to move local writing. Removed selections retain their remote copies
and private identities. No deletion propagation is supported.

Changing storage mode after first sync produces a conflict. Review
`conflict resolve --choice replace-storage` to create a replacement object while
retaining the previous object and binding history. No migration deletes the old
copy. Source relocation uses the constrained `source rebind` workflow described
in the recovery resource; do not change UUIDs or edit bindings to simulate it.
